## 1. 問題定義

ペルソナを注入しても、LLM の応答には**モデル由来の文章癖**が残る。口調（語尾・口癖）が
維持されていても、癖が出た瞬間に「中の人が AI」だと分かってしまう。AI 臭は 2 つの
性質に大別できる:

1. **均質性** — 個性や偏りがなく、どこを切っても同じ質感。熱量が一定で、
   すべての具体例が主張に従順に奉仕する。
2. **手癖** — 定型句・構文・比喩の反復（「重要なのは」「X ではなく Y だ」の対比連打、
   三拍子、英語比喩の直訳など）。

これは **intensity（口調の維持）とは直交する第 2 の品質軸**である。hersona は前者を
`measure` / `bench` で測れるが、後者「人間らしさ（naturalness）」は測っても抑えてもいない。

### 1.1 アーキテクチャ上の前提

> **禁止リスト型の指示（チェックリスト型プロンプト）単体では効果が限定的。**
> モデルは自分の AI 臭さを自己検出できず、指摘を受けて書き直しても
> 同型のパターンに着地しやすい。

このため本計画は「directive を書いて終わり」にせず、
**静的検知（機械的検出）・自己点検ループ・揺らぎ（偏り）の付与** の 3 点を
hersona の既存機構に対応付けて実装する:

| 仕組み | hersona での対応物 |
|---|---|
| 静的検知（regex による癖の機械検出） | **P1: naturalness スコア**（`measure` / `bench` / MCP。hersona の「決定的採点」ポジションと完全一致） |
| 自己点検ループ（「人間に AI くさいと指摘された」設定で再点検） | **P2b: naturalness 版 check prompt**（既存 `pre_response_check_prompt` の拡張）+ MCP `measure_intensity` / `bench_transcript` による自己採点→修正ループ |
| 揺らぎを作る（人間味 = 偏り） | **P2a: humanize directive の「偏り付与」節** — hersona はペルソナの `core_traits` / `examples` が偏りの供給源として既にあるため、一般文章より有利（キャラは偏っていてよい） |

### 1.2 既存資産との差分（重複回避）

| 既存 | カバー済み | 本計画が足す差分 |
|---|---|---|
| `response_style_directive`（attach.py） | 前置き・自己語り禁止 / 口癖・語尾のレパートリー運用 / 連続応答の反復防止 | humanize 節（§3 P2a: 手癖の禁止 + 偏りの付与）を同 directive に統合 |
| `intensity.py` / `bench.py` / MCP 自己採点ツール | 口調の維持率（語尾・口癖・一人称） | **naturalness スコア**（AI 臭の決定的採点）を別軸で追加 |
| `pre_response_check_prompt`（intensity.py） | 応答前の口調セルフチェック | naturalness 版セルフチェック（「人間に AI くさいと指摘された」フレーミング）を追加 |
| sharpen-and-grow **A-6**（examples few-shot 注入） | 実文アンカーで文体を寄せる | 本計画はルールで「削る」+ 偏りを「許す」側。A-6 の手本で「寄せる」側と相補 |
| `technical_distraction_en` シナリオ | AI 臭が最も出やすい「事務的質問」の器 | naturalness 列を bench 出力に足せば追加シナリオ不要で before/after が取れる |

## 2. AI 臭カタログ（測定・抑制の対象）

**会話応答（チャット）文脈**向けに 4 グループで定義する。すべて regex / 文字列で
決定的に検出できる表層シグナルに限定（ja / en。zh/ko は A-3 完了後）:

### A. 手癖語彙・定型句（辞書照合）

| 種別 | ja 例 | en 例 |
|---|---|---|
| 定型接客句 | かしこまりました / 承知いたしました / 素晴らしい質問 | Certainly! / I'd be happy to / Great question |
| メタ前置き | 重要なのは / 要するに / 本記事では / 結論から言うと | It's important to note / In summary |
| 締めの定型 | いかがでしたか / 参考になれば幸いです / 他にご質問があれば | I hope this helps / Let me know if |
| 逃げの定型 | ケースバイケースです / 〜というものです（締め直し） | It depends / generally speaking |
| 反論の先取り | 〜と思われるかもしれません | You might be wondering |
| AI 自己言及 | AI として / 私は AI | as an AI / language model |
| AI 頻出語・死んだ比喩 | 問い / 根源 / 器・受け皿 / 種をまく / 羅針盤 / 出血（英語比喩の直訳） | delve / tapestry / navigate / landscape |

### B. 構文・リズム癖（パターン照合 + 頻度閾値）

初期閾値は仮置きであり、会話向けに再較正する（§4-4）:

| ルール | 初期閾値（仮置き） |
|---|---|
| 否定→肯定の対比（「X ではなく、Y だ」） | 3 回以上で減点 |
| 三拍子の連打（「調べ、考え、書く」式） | 検出で減点 |
| 短い問いの連打（「〜か。」） | 3 連続で減点 |
| 助詞止め・省略の畳みかけ（「〜も。」「〜から。」） | 3 回以上で減点 |
| 「という」の密度 | 千字あたり 4 回以上で減点 |
| 「——」（ダッシュ）の多用 / 「では、〜か。」式の仕切り直し | 頻度で減点 |
| ヘッジの一律付与（文末が全部「〜かもしれません」） | 密度で減点 |

### C. 翻訳調・読みにくさ（統語プロキシ）

| ルール | 初期閾値（仮置き） |
|---|---|
| 100 字を超える一文 | 検出で減点 |
| 漢字 7 字以上の連続（漢語の積み上げ） | 検出で減点 |
| 一文に読点 4 つ以上 | 検出で減点 |

### D. 構造・応答様式（会話文脈固有）

| ルール | 検出 |
|---|---|
| 会話への箇条書き・見出し回答 | 箇条書き / 見出し行の比率 |
| 質問の復唱から始める | 冒頭文とユーザー発話の n-gram 重複（`bench --scenario` 併用時のみ） |
| 免責・注意書き | 辞書照合（ご注意ください / 専門家にご相談ください 等） |
| 文長の均質さ | 文長の変動係数が閾値未満で減点 |

> カタログ・閾値は `hersona/core/naturalness.py` 内の定数として持つ（属性カタログを
> 汚さない。将来コミュニティ拡張の需要が出たら YAML 化を検討）。

## 3. 対策の 3 本柱

### P1: 測定 — naturalness スコア（先に数字を作る）★工数 M

- 新モジュール `hersona/core/naturalness.py`:
  `measure_naturalness(text, *, lang="ja") -> NaturalnessReport`
  （100 点からの減点式 0–100。100 = 自然。内訳: §2 の A–D 分類別ヒット / 減点値）
- 実装は **表層のみ・決定的・stdlib のみ**（regex / 文字列。形態素解析等の依存は入れない。
  `intensity.py` と同じ割り切り: gaming 可は許容、再現性優先）
- CLI: `hersona measure ... --naturalness`（intensity レポートに naturalness 節を併記）、
  `hersona bench ... --naturalness`（ターン別 + 平均 naturalness 列。`--json` にも追加）
- MCP: `measure_intensity` / `bench_transcript` に `naturalness: bool = False` を追加
  （エージェントの自己採点ループが B-2 拡張と直結）
- テスト: `tests/test_naturalness.py`（A–D 各分類の対照テキスト、閾値境界、ja/en 系統）

### P2a: 抑制と偏り — humanize ディレクティブ（オプトイン）★工数 S

- `blend` / `export` / `soul` / `persistent` に `--humanize` フラグを追加
- 指示文は CLAUDE.md の規則どおり **`response_style_directive` に統合**（節を新設しない）。
  二部構成:
  1. **削る**: §2-A/B/D の手癖の禁止（定型句・網羅回答・免責・復唱・箇条書き・
     一律ヘッジ）+ 一文目から中身を始める（寒い書き出し禁止）
  2. **偏らせる**（人間味 = 偏り。禁止だけでは均質性に効かないため）:
     ペルソナが強い関心を持つ話題は長く・どうでもいい話題は短く（確信と重みのムラ）/
     立場の開示 / 変な具体性を 1 つ入れる — ただし **ペルソナの core_traits と
     会話の文脈に根ざす範囲で控えめに**（捏造・過剰演出を防ぐ制約を明記する）
- 想定コスト +60〜90 tok/ターン → **既定 OFF・オプトイン**（A-4 compact と逆方向の
  ダイヤル。プロファイル軸: compact ↔ standard ↔ humanize に整理）
- SKILL.md はフラグ 1 行の追記のみ（トークン規律維持）、詳細は REFERENCE.md へ

### P2b: 自己点検ループ ★工数 S

- `pre_response_check_prompt`（intensity.py 既存）に naturalness 版を追加:
  **「この応答を人間が読んで『AI くさい』と指摘された、という設定で読み直す」**
  フレーミング + §2 カタログの観察観点
  （「この一文、誰が書いても同じにならないか」等）
- 運用ループの文書化: 応答生成 → `measure --naturalness`（or MCP 自己採点）→
  閾値未満なら check prompt を末尾へ再注入 → 再生成。A-6 のリカバリループ・
  A-4 のキャッシュ prefix 非破壊（末尾追加）と同じ構造に載せる

### P3: 実証 — before/after の実測と既定化判断 ★工数 M

- A-2 基盤（`benchmarks/run_comparison.py`）に condition `a_humanize` を追加し、
  「humanize あり/なし」で **naturalness と maintenance の両方**を実測
  （humanize が口調維持を壊さないことも同時に確認する）
- **モデル別の naturalness 比較**も同枠で取る（モデルにより AI 臭の出方は大きく
  異なるため。cross-model 比較は A-2 の既存条件マトリクスにそのまま乗る）
- 結果を `docs/BENCHMARKS.md` に日付・モデル・再現コマンド付きで掲載（悪い数字もそのまま）
- 数字が出たら v2.0 で既定化を判断（A-6 と同じ進め方）

## 4. 測定の割り切り（honesty）

1. **表層プロキシである** — 測れるのは「AI 臭の徴候」であって人間らしさそのものではない。
   定型句を避けた不自然な言い換えは検出できない。
2. **自己汚染** — humanize directive の語彙と検出辞書は重なるため、directive を入れると
   スコアが「見かけ上」改善しうる（指標のゲーミング）。BENCHMARKS では
   「humanize 注入あり」を別列で報告し、素の値と混ぜない（A-6 と同じ規律）。
3. **英語統語の残存** — 無生物主語・受動態の多用・代名詞の多用・助詞の省略しすぎ
   といった英語由来の統語癖は、形態素解析なしの決定的検出が困難またはノイズが大きい。
   **P1 のスコア対象にはせず**、既知の限界として文書化する（モデルは自分の英語的構文を
   自然と感じており、書き直しても同型に着地しやすい — directive でも消しにくい領域）。
4. **閾値の再較正が必要** — §2-B/C の初期閾値は長文向けの仮置き。hersona の主戦場は
   数十〜数百字の会話応答であり、絶対回数の閾値は文字量あたりに正規化して P1 実装時に
   対照テキストで較正する。
5. **復唱検出はシナリオがある時のみ** — ユーザー発話との n-gram 重複はトランスクリプト
   単体では測れない。`bench --scenario` 併用時に限定する（P1 では任意実装）。

## 5. やらないこと（スコープ規律）

- **LLM-judge による人間らしさ採点** — 「軽量・決定的」ポジションに反する
  （`IMPROVEMENT_DISCUSSION_2026-06-15.md` §2 の却下方針を踏襲）。特定の書き手の
  文体を学習・蒸留する「文体の再現」系の機能も執筆支援ツールの領分であり、
  ペルソナ注入層である hersona はやらない
- **perplexity / AI 検出器ベースの測定** — モデル依存・非決定的
- **AI 検出ツールの回避を目的とする機能・訴求** — 本計画の目的はペルソナ会話の品質
  （キャラクターとして自然であること）であり、生成物の出自を偽装する用途には
  位置づけない（README / 発信でもそのように書かない）
- 形態素解析・NLP ライブラリの追加依存（runtime deps は pyyaml + jsonschema のまま）
