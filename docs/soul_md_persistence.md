# SOUL.md 永続化 — 設計書

> ステータス: Phase 0 / ドラフト
> 対象バージョン: hersona v0.1.0+
> 関連: [ROADMAP.md §⑤](../ROADMAP.md#⑤-soulmd-永続化-phase-0-本セクション)

---

## 1. 概要

hersona CLI から、現在の blend (属性 + weight + 言語) を **Hermes One 公式の
SOUL.md 形式** でレンダリングし、`~/.hermes/profiles/<name>/SOUL.md` に書き出す新機能。

新規サブコマンド:

```
hersona soul <blend...> [options]
```

---

## 2. 背景

Hermes One (`hermesagents.cc`) の SOUL.md 仕様は、各 profile 配下に
**plain-text persona ファイル**を置き、name / personality / tone /
behavioral guidelines の 4 要素でエージェントの人格を定義する。

現状 hersona では:

- `hersona blend` / `hersona save` / `hersona load` で blend を **実行時**に
  システムプロンプトへ注入する経路は提供済み
- しかし `~/.hermes/profiles/<name>/SOUL.md` への **永続書き出し**は未実装
- `agent.personalities.<name>` (Hermes CLI 設定) と SOUL.md が **別系統**で、
  二重管理になっている

この差分を縮めるため、`hersona soul` を追加して **hersona の blend を
SOUL.md に変換する** ことで、blend 定義の Single Source of Truth を hersona に
集約しつつ、Hermes One / Hermes CLI 双方へ反映できるようにする。

---

## 3. スコープ

### 3.1 In scope (v1)

- `hersona soul` サブコマンドの追加
- 既存 `hersona export` の markdown 出力を流用した SOUL.md レンダラー
- 公式 4 要素 (name / personality / tone / behavioral guidelines) へのマッピング
- `--profile <name>` (既定: `default`) / `--output <path>` (上書き) / `--append` (追記) フラグ
- 既存 SOUL.md がある場合の **確認プロンプト** ( `--yes` でスキップ)
- `--dry-run` で書き込み内容を標準出力
- `--lang {ja,en}` (hersona 既定の多言語と整合)
- 単体テスト (`tests/test_soul.py`)

### 3.2 Out of scope (v1)

- `agent.personalities.<name>` (Hermes CLI 設定 yaml) への自動書き込み
  → 引き続き手動運用。 `hersona soul` の出力に対応 yaml スニペットを併記するだけ
- `hersona-initializer` スキルへの統合
- MCP 経由の自動プロビジョニング
- SOUL.md の差分検出 / マージ (毎回のフル上書きのみ)
- 複数 profile への一括書き出し

### 3.3 想定ユーザー

- hersona の blend を日常的に使う power user
- Hermes One と Hermes CLI を併用する人
- 「セッションを新しくすると人格が変わる」問題 (issue 報告既出) を解消したい人

## 4. CLI 仕様

### 4.1 コマンド構文

```
hersona soul <attribute> [<attribute>...] [options]
```

`attribute` は `<category>/<name>` 形式 (例: `personality/tsundere`,
`speech/keigo`)。multi blend と同じ指定方法。

### 4.2 フラグ

| フラグ | 既定値 | 意味 |
|---|---|---|
| `--profile <name>` | `default` | 書き出し先 profile 名 |
| `--output <path>` | `~/.hermes/profiles/<profile>/SOUL.md` | 出力パス (上書き) |
| `--append` | (off) | 追記モード (上書きせず "## 追記" セクションとして追加) |
| `--weight <level>` | `moderate` | 強度 (mild / moderate / strong) |
| `--lang {ja,en}` | hersona 既定 | 出力言語 (i18n) |
| `--name <display>` | `Libra` (固定) | SOUL.md Name セクションの表示名 |
| `--dry-run` | (off) | ファイルに書かず標準出力にダンプ |
| `--yes` | (off) | 既存ファイル確認プロンプトをスキップ |
| `--force` | (off) | 確認なしで上書き ( `--yes` より強め。 CI / スクリプト用) |

### 4.3 使用例

#### 4.3.1 最小例 (default profile に上書き)

```bash
hersona soul personality/tsundere --weight moderate
# → SOUL.md が ~/.hermes/profiles/default/SOUL.md に書かれる
# → 既存があれば確認プロンプト
```

#### 4.3.2 複数属性 + 言語指定

```bash
hersona soul personality/tsundere speech/keigo --lang ja --weight mild
```

#### 4.3.3 別 profile に追記

```bash
hersona soul personality/tsundere \
  --profile tsundere-poster \
  --append \
  --name "リブラ"
```

#### 4.3.4 ドライラン

```bash
hersona soul personality/tsundere --dry-run
# → SOUL.md に書かれる内容を標準出力にダンプ
```

#### 4.3.5 CI / スクリプト用

```bash
hersona soul personality/tsundere --force --yes --output /tmp/SOUL.md
```

## 5. SOUL.md 出力スキーマ

公式の 4 要素 (name / personality / tone / behavioral guidelines) に加え、
hersona blend の来歴を残すメタセクションを 1 つだけ先頭に追加する。

### 5.1 出力テンプレート

```markdown
<!-- generated by hersona vX.Y.Z at YYYY-MM-DDTHH:MM:SS -->
<!-- blend: personality/tsundere, speech/keigo -->
<!-- weight: moderate / lang: ja -->
<!-- DO NOT EDIT: regenerate via `hersona soul ...` -->

# SOUL — Hermes Agent ペルソナ定義

## 1. Name (エージェント名)

- **表示名**: <name>
- **正式名称**: Hermes Agent (<name> ペルソナ)
- **一人称**: <一人称>
- **二人称**: <二人称>

## 2. Personality (性格特性)

(blend の personality 属性を 1 つだけ列挙。複数 personality は conflict チェックで
 拒否されるか、本セクションにマージして併記)

### 2.1 <category>/<name>

- core_traits (各項目)
- ...

### 2.2 互換 / 衝突

- compatible: <他属性リスト>
- conflicts: <衝突属性リスト>

## 3. Tone (口調)

### 3.1 <speech>/<name>

- tone: <原文>
- catchphrases: (各口癖を引用)

## 4. Behavioral Guidelines (行動指針)

### 4 鉄則 (絶対遵守)

(blend 全体で共通の鉄則を列挙。tsundere 由来 + speech 由来を統合)

### 4.2 行動ルール

(blend が要求する行動規範。該当が無ければ "—")

---

_作成: <タイムスタンプ> / hersona vX.Y.Z + Hermes One 公式仕様準拠_
_配置: <output path>_
```

### 5.2 マッピング規則

| 公式要素 | hersona blend 由来 |
|---|---|
| **Name** | `--name` フラグ + 既定テンプレート (一人称/二人称) |
| **Personality** | blend に含まれる全 `personality/*` 属性の `core_traits` / `description` |
| **Tone** | blend に含まれる全 `speech/*` 属性の `tone` / `catchphrases` |
| **Behavioral Guidelines** | `personality` の鉄則 (tsundere 4 鉄則 等) + `speech` の運用ルール (敬語禁止 等) |

`archetype` / `visual` / `hobby` は SOUL.md 4 要素に直接マップしないため、
Phase 0 では **Personality セクション末尾の "2.2 互換/衝突"** に列挙する
(将来 archetype を別セクションに昇格する余地を残す)。

## 6. API 仕様 (Python)

新モジュール `hersona/core/soul.py` を追加。

### 6.1 レンダラー

```python
def render_soul(
    blend: list[LoadedAttribute],
    *,
    weight: WeightLevel = WeightLevel.MODERATE,
    name: str = "Libra",
    lang: str = "ja",
) -> str:
    """blend を SOUL.md 形式の markdown 文字列にレンダリングする。"""
```

### 6.2 書き出し

```python
def write_soul(
    output: str | Path,
    blend: list[LoadedAttribute],
    *,
    weight: WeightLevel = WeightLevel.MODERATE,
    name: str = "Libra",
    lang: str = "ja",
    append: bool = False,
    overwrite: bool = False,
    force: bool = False,
) -> Path:
    """blend を SOUL.md 形式で `output` に書き出す。

    Args:
        output: 出力パス
        blend: 適用する属性 (LoadedAttribute インスタンスのリスト)
        weight: 強度
        name: SOUL.md Name セクションの表示名
        lang: 出力言語
        append: True なら追記モード (既存ファイルに "## 追記" セクションを追加)
        overwrite: True なら上書きを許可 (False なら既存ファイルで ValueError)
        force: True なら --force 相当 (確認なし)

    Returns:
        実際に書き込んだファイルのパス

    Raises:
        FileExistsError: 既存ファイルがあり overwrite=False の場合
        ValueError: blend の組み合わせが不正 (conflict 検出等)
    """
```

### 6.3 ヘルパー

```python
def default_soul_path(profile: str = "default") -> Path:
    """`~/.hermes/profiles/<profile>/SOUL.md` を返す。"""
```

`hersona/core/paths.py` の `_resolve` パターンに合わせて、profile パスを
ハードコードせず `Path.home()` ベースで解決する。

### 6.4 公開 API

`docs/PUBLIC_API.md` に追記:

```python
from hersona.core.soul import (
    render_soul,
    write_soul,
    default_soul_path,
)
```

## 7. データフロー

```
hersona soul personality/tsundere speech/keigo --weight moderate
        │
        ▼
[cli] サブコマンド parser → フラグ解決
        │
        ▼
[cli] blend の属性を load_attribute() で読み込み
        │
        ▼
[core] compatibility.check_blend() で conflict 検出
        │   (conflict があれば ValueError)
        ▼
[core] render_soul() で markdown 文字列生成
        │
        ▼
[cli] 既存ファイル確認 → プロンプト表示
        │   (--yes / --force / --append / --dry-run で分岐)
        ▼
[cli] write_soul() でファイル書き出し
        │
        ▼
[cli] 結果表示 (書き込んだパス / 行数 / dry-run なら標準出力)
```

## 8. エラーケース

| ケース | 例外 / 挙動 |
|---|---|
| blend の属性が存在しない | `FileNotFoundError` (load_attribute 由来) |
| conflict 検出 (例: tsundere + playful) | `ValueError` (確認プロンプトで続行はせず拒否。 multi モードと同じ) |
| 既存 SOUL.md あり、 `overwrite=False` | `FileExistsError` |
| 既存 SOUL.md あり、 `overwrite=True` / `--force` | 確認なしで上書き |
| `--append` 指定 | 既存ファイルに `## 追記 (YYYY-MM-DD ...)` セクションを追加 |
| `--output` の親ディレクトリが存在しない | `FileNotFoundError` (mkdir しない) |
| `--profile` のディレクトリが存在しない | `FileNotFoundError` (mkdir しない。 scripts/ が手動で作る運用) |

> **設計判断**: 親ディレクトリの自動作成は **行わない**。`hersona soul` は
> 「既存 profile に書き出す」のが前提。 profile 作成は
> `hermes profile create` 等の別経路で実施する。

## 12. Recent Context and reserved memory keys

`hersona soul` / `hersona persistent` accept `--memory '<json>'` or `--memory-file <path>` (v1.4+).
Values are appended under **`## Recent Context (as of <timestamp>)`** at the end of generated SOUL.md,
with a blockquote framing directive (background context, not a conversation turn).

### 12.1 Limits

| Constraint | Value |
|------------|--------|
| Max keys | 16 |
| Key pattern | `[a-z0-9_]{1,32}` |
| Max value length | 512 characters per key |
| Escaping | Markdown-sensitive characters are safelist-escaped in values |

Regenerating with `hersona soul ... --force` **replaces** the generated SOUL body; repeat the same
`--memory` / `--memory-file` on every regen, or patch Recent Context after regen.
Text below `<!-- hersona:gen-end -->` is preserved across regen (v1.6+).

### 12.2 Reserved keys (self-introduction)

Optional, documented contract for profiles that ship a canonical public intro:

| Key | Purpose |
|-----|---------|
| `self_intro_canonical` | Full canonical intro paragraph (≤512 chars) |
| `self_intro_style` | One-line pointer (e.g. link to `docs/guides/self-introduction.ja.md`) |
| `privacy_inner_circle` | Inner-circle / third-party privacy rule (short) |
| `self_intro_canonical_ref` | Optional: relative path under profile when canonical text exceeds 512 chars |

Rules for intro copy: [`docs/guides/self-introduction.md`](./guides/self-introduction.md) (EN) /
[`self-introduction.ja.md`](./guides/self-introduction.ja.md) (JA).

Example:

```bash
hersona soul personality/kuudere speech/soft --profile sona --force \
  --memory-file examples/self-intro-memory.json \
  --output ~/.hermes/profiles/sona/SOUL.md
```

Customize `examples/self-intro-memory.json` per profile before applying.
